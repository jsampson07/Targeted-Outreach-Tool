    - Treat as a placeholder pending real reconciliation / deliverability observation — same documentation pattern as the confidence-score formula (Deviations #12). Do not invent different thresholds without an explicit decision to replace this one.
23. **Hunter tier-matching locked as case-insensitive substring match** of email `position` against each tier's `role_titles` list. Intentionally simple — no fuzzy matching, no LLM title classification. Unvalidated against real title vocabulary noise; revisit only with observed false-positive/false-negative data.
24. **`CONTACT_PROVIDER` settings flag** (`Literal["mock","hunter"]`, default `"mock"`) plus optional `HUNTER_API_KEY`. Router builds the provider list from settings rather than hardcoding `MockProvider()`. Default deliberately spends zero Hunter credits during routine local/dev use — real-key checkpoint validation is manual and out of band.
25. **Hunter credit-conservation cache is instance-local, in-process, keyed by `company_domain`.** First `search()` for a domain performs one Domain Search HTTP call (`limit=100`); later tier calls in the same discovery run re-filter the cached raw emails (or replay a cached `RATE_LIMITED`/`ERROR` without retry). This does **not** violate `ARCHITECTURE.md` §4.3 — no DB handle, no awareness of the Postgres `COMPANIES`/`CONTACTS` cache; it only avoids spending 4 Hunter credits on the 4 orchestrator tier calls that reuse one provider instance. Pagination beyond the first 100 emails is not implemented (would cost extra credits).
